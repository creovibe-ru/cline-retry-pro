# Cline Retry Pro

Cline (`saoudrizwan.claude-dev`) останавливает задачу и показывает кнопку **Retry**,
как только провайдер отвечает «временно перегружен». Этот патч заставляет его
повторять запрос сам — с нарастающей паузой, до 12 раз, примерно 8 минут.

---

## Установка одной командой

Откройте PowerShell (**не** от администратора) и выполните:

```powershell
iex ((irm https://raw.githubusercontent.com/creovibe-ru/cline-retry-pro/main/install.ps1).Trim([char]0xFEFF))
```

Скрипт сам найдёт Cline (VS Code, Insiders, Cursor, Windsurf), скачает два
патчера в `%LOCALAPPDATA%\cline-retry-pro`, применит их и напечатает отчёт.

Затем **перезагрузите окно редактора**: `Ctrl+Shift+P` → `Developer: Reload Window`.

Всё. Больше ничего настраивать не нужно.

> **Почему `.Trim([char]0xFEFF)`?** Файл сохранён в UTF-8 с BOM, иначе PowerShell 5.1
> показывал бы русский текст кракозябрами. При `iex` этот невидимый символ в начале
> строки ломает разбор скрипта (`Непредвиденный атрибут "CmdletBinding"`), поэтому
> его нужно отрезать — ровно это и делает `.Trim(...)`.
>
> **Альтернатива без `iex`** (обходит и политику выполнения, если она запрещает всё):
> ```powershell
> $f="$env:TEMP\cline-retry-pro.ps1"; irm https://raw.githubusercontent.com/creovibe-ru/cline-retry-pro/main/install.ps1 -OutFile $f; powershell -NoProfile -ExecutionPolicy Bypass -File $f
> ```

## Что исправляется

| Симптом в Cline | До патча | После патча |
|---|---|---|
| `Upstream capacity is temporarily exhausted. Retry shortly.` | задача встаёт, нужен ручной Retry | повтор автоматически |
| `429 Too Many Requests`, `503 Service Unavailable` | повтор был, но быстро заканчивался | до 12 попыток, ~8 минут |
| ошибка пришла уже **во время стрима** ответа | не повторялось вообще | повторяется |
| обрыв на середине ответа | блокировал повтор | не блокирует (важен только уже выполненный tool-call) |
| `reasoning_content ... must be passed back` (400) | — | **сознательно не повторяется**, см. ниже |

### Почему раньше не работало

Cline решает «повторять или нет» по HTTP-статусу ошибки и по одной регулярке
`/provider returned error/i`. Текст `Upstream capacity is temporarily exhausted`
приходит **без статуса** и не подходит под эту регулярку — поэтому
`retryable = false`, и цикл повторов не запускается ни разу. Плюс стоял жёсткий
запрет на повтор ошибок, возникших в фазе `stream_callback`.

Патч меняет три вещи в минифицированных бандлах:

1. **Лимиты**: `maxRetries`, базовая пауза и потолок паузы.
2. **Классификатор**: расширенный список текстовых признаков временной ошибки —
   `capacity exhausted`, `overloaded`, `rate limit`, `temporarily unavailable`,
   `retry shortly` и др.
3. **Стрим**: снят запрет `phase!=="stream_callback"`, а guard частичного ответа
   больше не срабатывает на обычный текст (только на выполненный tool-call).

## Про ошибку `reasoning_content`

`The reasoning_content in the thinking mode must be passed back to the API` — это
ответ **400**, а не сетевой сбой. Повтор упадёт точно так же, потому что дело в
истории диалога, а не в доступности провайдера. Поэтому она намеренно остаётся
неретраибельной.

Что делать: начать новую задачу (история не переносится) или отключить режим
размышлений для этой модели у провайдера.

## Проверка, откат, удаление

Если репозиторий склонирован локально:

```powershell
.\install.ps1 -Mode Verify   # только показать состояние, ничего не менять
.\install.ps1 -Mode Revert   # вернуть оригинальные файлы из бэкапов
.\install.ps1 -Uninstall     # снять задачу планировщика и откатить патч
```

Без клонирования:

```powershell
$u='https://raw.githubusercontent.com/creovibe-ru/cline-retry-pro/main/install.ps1'
$s=[scriptblock]::Create((irm $u).Trim([char]0xFEFF))
& $s -Mode Verify
& $s -Mode Revert
& $s -Uninstall
```

Патч состоит из двух частей (тайминги и логика) и обе правят одни и те же
бандлы, поэтому `-Mode Revert` снимает их в обратном порядке — сначала логику,
затем тайминги. В любом другом порядке вернулся бы бэкап, снятый уже после
части патча, и файл остался бы изменённым.

Если у файла нет бэкапа (например, его когда-то пропатчили вручную), `Revert`
честно скажет «вернуть оригинал нечем» и предложит переустановить расширение
из VS Code — после этого установщик снова создаст бэкапы.

Типичный вывод `-Mode Verify`:

```
  файл: dist\extension.js
    объявление: _mn=12,ccp=2e3,dcp=60e3
    maxRetries=12 (_mn)
    baseDelay=2e3 мс (ccp)
    maxDelay=60e3 мс (dcp)
    состояние: ПАТЧ ПРИМЕНЁН, бэкап есть
  файл: dist\plugin-runtime\node_modules\@cline\core\dist\index-fqa2d9rz.js
    классификатор временных ошибок: применён
    повтор после ошибки в стриме: применён
    частичный ответ и повтор: нет в этом файле
```

Каждый признак печатается в одном из четырёх состояний: `применён`,
`не применён`, `нет в этом файле` (в этом бандле такого кода нет) и
`не определить без бэкапа`.

## После обновления Cline

Обновление расширения создаёт новую папку версии — патч туда не попадает.
Два варианта:

* запустить `install.ps1` заново;
* один раз выполнить установку с `-InstallTask` — тогда задача планировщика
  переприменяет патч при каждом входе в систему:

```powershell
$u='https://raw.githubusercontent.com/creovibe-ru/cline-retry-pro/main/install.ps1'
& ([scriptblock]::Create((irm $u).Trim([char]0xFEFF))) -InstallTask
```

Удалить задачу: `-Uninstall`.

## Безопасность

* Перед изменением каждого бандла рядом создаётся бэкап `*.cline-autoretry*.bak`.
* После записи файл перечитывается и проверяется; при расхождении он
  автоматически восстанавливается из бэкапа.
* Если структура бандла не совпала (другая версия Cline), скрипт ничего не
  меняет и честно сообщает об этом — расширение не ломается.
* Никаких сетевых запросов, кроме скачивания двух патчеров с этого репозитория.
* Патч локальный: он живёт до следующего обновления расширения и снимается
  одной командой.

## Ограничения

* Это не расширение из Marketplace: VS Code не позволяет сторонним расширениям
  править чужие бандлы, поэтому распространяется скриптом.
* Правки привязаны к структуре конкретных версий Cline (проверено на 4.1.26).
  На другой версии скрипт либо применится, либо аккуратно откажется.
